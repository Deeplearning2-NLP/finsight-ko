# 발표 질의응답 준비 (10/23 프로포절)

예상 질문마다 2–3문장 답변 초안. 숫자는 모두 `docs/proposal-results.md`에서 가져왔고 괄호에 절 번호를 적었다. 발표에서 "주장하는 개선"은 decisions 2026-10-21 기준(문단 클러스터 부트스트랩 CI가 0을 넘는 것)만 쓴다. 투자 권유 아님.

## 교수님 공통 가이드의 예상 질문

**1. 데이터를 실제로 갖고 있나?**
네. 평가 대상 10개사 × 사업연도 2022–2024 사업보고서 원문 30건을 OpenDART에서 받아 직접 파싱했고, 청크 34,427개가 있습니다(9.1). 학습용 20개사 원문 60건(청크 48,712개)도 있습니다(11.2). 수치 정답 169칸은 OpenDART 재무제표 API 값이고(9.2), 이것으로 만든 수치형 문항 369개도 이미 있습니다(9.3).

**2. 라벨은 누가, 어떤 기준으로 만드나?**
수치 문항의 정답은 사람이나 LLM이 아니라 OpenDART 공식 값을 `account_id`로 매핑한 것입니다. 재작성(restatement)된 28문항은 두 값을 모두 인정합니다(9.2, 10.1). 서술·비교 문항은 가이드(`docs/eval_guideline.md`)를 따라 30%를 사람이 쓰고, 근거 청크 ID를 직접 지정합니다. 검수 기준은 "명확성 / 정답 단일성 / 근거가 답을 담는가"이고, 30문항은 2명이 교차 검수해 Cohen's κ를 보고합니다(10.5). 질문 메타데이터 평가용 라벨 130개는 Claude Code 세션이 추출기 출력을 보기 전에 규칙을 정하고 하나씩 읽어 붙였습니다(11.1). 팀원이 일부를 다시 확인할 예정입니다.

**3. 기준선과 직접 학습한 모델은 무엇이고, 얼마나 다른가?**
기준선은 공백 BM25 → 형태소(Kiwi) BM25 → 공개 임베딩 KURE-v1 순서입니다. 직접 학습한 모델은 평가와 겹치지 않는 20개사의 원문에서 만든 질문–문단 5,000쌍으로 대조 학습한 KURE입니다. 정직하게 말하면, test 1,947문항에서 공개 모델 대비 R@5 +1.7%p이고 CI [−2.0, +5.3]으로 아직 유의하지 않습니다(12.2). 평가와 같은 회사로 학습한 스모크는 +5.6%p였는데, 그 이득 대부분이 같은 회사 효과였다는 것을 회사를 분리해서 확인했습니다. 다만 질문에 사업연도가 있으면 R@5가 0.627 → 0.730으로 크게 오릅니다. 학습 질문의 스타일(연도·회사 명시)을 평가 질문과 맞추는 것이 다음 단계입니다(12.2).

**4. 학습 데이터와 평가 데이터는 어떻게 분리하나?**
회사 단위로 분리합니다. 평가는 10개사이고, 학습 쌍은 겹치지 않는 20개사의 원문에서만 만들며, 코드에서 겹침이 없음을 assert합니다(11.2). 예비 실험(FinDartBench)도 doc_id·문단을 연결 성분으로 묶어 train/dev/test가 문단을 공유하지 않게 나눴습니다(5절). 하이퍼파라미터와 조합은 dev로만 고르고, test에서 영감을 얻은 것은 따로 밝힙니다(11.1의 연도 창).

**5. 기존 연구·데이터와 무엇이 다른가?**
공개 코퍼스 Dartdoc은 표 숫자가 빠져 있고, 대형사의 2022–2023 보고서도 거의 없습니다(FinDartBench 10개사 중 7개사, 2절). 그래서 원문 XML을 직접 파싱해 표를 살렸고, 수집·파싱 함정 5가지를 찾아 고쳤습니다(9.1, 11.2). 깨진 XML 3가지, 같은 이름의 회사 코드 2건이고, 고치기 전에는 섹션이나 보고서가 통째로 빠졌습니다. 또 공시의 접수일/사업연도, 정정공시, 재작성 같은 함정을 평가 규칙에 반영했습니다(2절, 10.1). 질문에서 회사·사업연도를 뽑아 필터로 쓰는 한국어 규칙 모듈도 직접 만들었습니다(11.1).

**6. 계획대로 안 되면?**
단계마다 이미 숫자가 있어서, 미세조정이 기대만큼 안 올라도 "형태소 BM25 + 메타데이터 필터 + 하이브리드"라는 결과가 남습니다. 예: 필터는 R@1 +5.6%p, CI [+4.0, +7.6](11.1). 학습 쌍 품질이 문제면 이번처럼 원천을 바꾸고 자동 필터를 강화합니다. Dartdoc 43% → 원문 80%가 그 예입니다(10.6, 11.3). 시간이 부족하면 에이전트·데모는 빼고 검색 + 수치 검증까지만 합니다(CLAUDE.md 범위).

## 우리 프로젝트에 나올 만한 질문

**7. 왜 R@1은 안 올랐나?**
미세조정 단독으로는 R@1이 오르지 않았습니다. 회사 분리 학습 (a)는 공개 모델 대비 −0.1%p, CI [−3.2, +3.1]입니다(12.2). 오류 분석에서 1위가 같은 회사·같은 섹션의 **다른 사업연도** 문단인 경우가 가장 많았고(30건 중 9건, 10.4), 다른 사업연도 hard negative를 넣어도 이 비율은 24.4% → 24.1%로 그대로였습니다(12.2). 연도 혼동의 대부분이 질문에 연도가 없는 경우에 몰려 있어서입니다(연도 없는 질문 30% vs 있는 질문 11%). 대신 질문에서 회사·연도를 뽑아 필터로 쓰면 R@1이 0.299 → 0.355로 유의하게 오릅니다(11.1).

**8. FinDartBench는 LLM이 만든 질문인데 믿을 수 있나?**
그대로 믿지는 않습니다. 예비 결과로만 씁니다. LLM 질문은 문단 단어를 베끼는 경향이 있어 BM25에 유리할 수 있고(5절), 오류 30건 중 3건은 라벨·매핑 문제였습니다(10.4). 회사나 연도가 없어 정답이 여럿인 질문도 많습니다. 사업연도를 말하는 질문이 43%뿐입니다(11.1). 그래서 결론은 사람이 30%를 쓰고 근거를 직접 지정한 자체 평가셋 약 200문항으로 냅니다(10.5).

**9. 입력을 왜 512토큰으로 고정하나?**
BERT 계열 임베딩(KURE-v1)과 재정렬기의 운영 조건을 같게 두고, 비교를 공정하게 하기 위해서입니다. 대신 원문을 512 이하로 다시 나눠 초과 청크가 0입니다(9.1, 11.2). 고정하지 않고 자르기만 하면 손해가 큽니다. FinDartBench 근거 문단의 88%가 512를 넘고, 잘라서 넣으면 KURE R@1이 0.642 → 0.434로 떨어집니다(3절, 5절).

**10. 생성 LLM과 시스템 LLM을 왜 나누나?**
질문을 만든 모델이 답도 하면, 자기 말투·어휘에 맞춰진 질문이라 점수가 부풀 수 있습니다. 그래서 학습 쌍은 서버의 오픈 모델(Qwen2.5-7B-Instruct)로 만들고, 답변 시스템은 다른 계열(EXAONE 등)로 합니다(decisions 2026-10-20). 오픈 모델이라 비용이 0이고, 같은 seed로 다시 돌리면 결과가 똑같이 나옵니다(10.6).

**11. 연도 오라클 R@1 0.674는 실제로 가능한가?**
그대로는 아닙니다. 오라클은 정답 사업연도를 아는 상한입니다(10.3). 실제 추출 필터로는 0.355이고, 격차의 15%를 메웠습니다(11.1). 하지만 질문에 연도가 있는 경우만 보면 R@1이 0.380 → 0.536까지 오릅니다. 평가셋 가이드에서 사업연도 명시를 규칙으로 정한 이유입니다(11.1, 10.5). 남은 차이는 "사건 연도 ≠ 보고서 연도"(예: 2023년 발표 전략이 FY2024 보고서에 실림)처럼 연도를 아는데도 범위가 어긋나는 경우와, 연도가 없는 질문에서 나옵니다(11.1).
