# 평가셋 작성 가이드 (팀 공용)

평가셋 약 200문항(dev 50 / test 150)을 만들 때 모두가 같은 규칙을 따르기 위한 문서. 범위·규칙의 근거는 `CLAUDE.md`, `docs/decisions.md`, 유형별 예시는 `docs/question_types.md`.
투자 권유 아님.

## 1. 범위와 공통 규칙
- 대상: 10개사(삼성전자, SK하이닉스, LG전자, 현대자동차, 기아, SK텔레콤, 한국전력공사, 국민은행, HMM, 두나무) × 사업연도 2022–2024 사업보고서 30건. 근거는 `data/processed/corpus_a.jsonl`의 청크.
- **질문에 반드시 쓰는 것:** 회사명(코퍼스의 `corp_name` 표기), 사업연도("2024 사업연도", 접수 연도가 아님), 재무 수치면 연결/별도.
  - 예외: 5유형(답 없는 질문)과, 일부러 "연도 없는 질문"을 시험하려는 문항은 `notes`에 그 이유를 적는다.
  - 이유: P4에서 1위 결과의 29.4%가 같은 회사·같은 섹션의 다른 사업연도였다. 연도가 없는 질문은 정답이 사실상 3개라 평가가 흔들린다.
- 정정공시: 같은 사업연도는 최신 접수본만 쓴다 (코퍼스는 이미 최신본). 보고서 이름에 `[기재정정]`이 있어도 그 보고서가 정답 출처다.
- 연결(CFS)이 OpenDART에 없어서(`013`) 별도(OFS)를 쓰면 질문과 정답에 "별도"라고 쓴다. 현재 국민은행 FY2022는 CFS·OFS 모두 없으니 수치 문항에서 뺀다.

## 2. 유형별 정의와 정답 형식
| 유형 | 정의 | 정답 형식 (`answer_*` 필드) | 근거 |
|---|---|---|---|
| 1 단일 수치 | 한 회사·한 사업연도·계정 1개 | `answer_value` (원 단위 float), `answer_unit: "원"` | OpenDART 계정(`source.account_id`) + 해당 표 청크 ID |
| 2 연도 비교 | 같은 회사, 두 사업연도 | 수치: 증감액을 `answer_value`, 증감률·두 값은 `answer_extra` / 서술: `answer_text` | 나중 사업연도 보고서의 표 청크 (당기·전기가 한 표에 있음) |
| 3 기업 비교 | 같은 업종 두 회사, 같은 사업연도, 공통 계정 | 차이(절댓값)를 `answer_value`, 큰 쪽 회사는 `answer_extra.larger` | 두 회사 각각의 청크 ID |
| 4 서술 요약 | 사업의 내용·위험 요인·시장 상황 요약 | `answer_text` (2–4문장) + 핵심 사실 목록 `answer_points` | 근거 청크 ID 1개 이상 |
| 5 답 없는 질문 | 사업보고서에 원래 없는 정보 (미래 주가, 개인 정보, 공시 대상이 아닌 내부 수치) | `answer_text: "보고서에서 확인할 수 없음"`, `gold_chunk_ids: []` | 없음 |

- 숫자는 원 단위로 바꿔 적는다 (`finsight.numbers.parse_krw`: 표의 "(단위: 백만원)"을 꼭 반영). 음수(△, 괄호)는 음수로.
- 5유형은 "범위 밖이지만 실제로는 공시된 정보"(예: FY2025 실적)로 만들지 않는다 (decisions 2026-10-20).

### 재작성(restatement) 규칙 (decisions 2026-10-20)
- **단일 수치:** 그 사업연도 보고서의 값이 정답. 나중 보고서에서 다시 쓴 값이 있으면 `answer_alt`에 넣는다.
- **연도 비교:** 나중 사업연도 보고서의 당기·전기 쌍이 기본 정답(2년 차이면 당기·전전기). 처음 보고된 값으로 계산한 증감은 `answer_alt`에.
- **채점:** `finsight.grading.grade_value` — `answer_value` 또는 `answer_alt` 중 하나와 0.5% 안이면 정답. 결과 보고에는 재작성 문항 수와 그 문항만의 점수를 따로 적는다.
- 예: LG전자 연결 매출액. FY2023 보고서 84,227,765백만원 → FY2024 보고서의 전기 값 82,262,664백만원 (−2.33%).
  - "LG전자 2023 사업연도 연결 매출액은?" → 정답 84.23조, `answer_alt` [82.26조]
  - "LG전자 연결 매출액은 2023 대비 2024 사업연도에 얼마나 변했나?" → 정답 +5.47조(+6.64%, 2024 보고서 기준), `answer_alt` [+3.50조(+4.16%)]

## 3. 근거 청크 ID 기록법
- `gold_chunk_ids`: `corpus_a.jsonl`의 `chunk_id` (`<rcept_no>_<4자리 순번>`) 리스트. **여러 개 허용**: 답이 두 청크에 걸치거나 같은 내용이 여러 섹션에 있으면 모두 적는다.
  - 예: HMM FY2023의 "홍해 사태로 인한 수에즈 운하 우회" 문단은 II.7 `20240328001188_0047`과 IV `20240328001188_0495`에 둘 다 있다 → 둘 다 정답.
- 청크는 `[섹션 경로]` 머리말로 시작한다. 근거를 찾을 때는 회사·사업연도로 먼저 거르고 섹션 경로로 좁힌다.
- 답이 표에 있으면 표 머리글이 있는 청크를 우선 적는다 (청크가 나뉘면 머리글이 반복되므로 값이 있는 청크에도 단위가 있다).
- 수치 문항은 `source`에 `rcept_no, account_id, fs_div`도 같이 적는다 (OpenDART 값과 대조용).

## 4. 사람이 직접 쓰는 문항 (약 30%, 60문항 안팎)
LLM 문항은 원문 단어를 그대로 쓰는 경향이 있어서 BM25에 유리하다 (AutoRAG·FinDartBench에서 확인). 사람 문항은 이 편향을 줄이는 것이 목적이다.

작성 순서:
1. **원문을 보지 않고 먼저 질문을 쓴다.** 투자자·기자·학생이 실제로 물을 법한 말로 쓴다 ("영업이익 얼마?"보다 "작년보다 돈을 더 벌었나?" 같은 말투도 허용).
2. 그다음 코퍼스에서 근거를 찾아 `gold_chunk_ids`와 정답을 채운다. 근거가 없으면 질문을 고치거나 5유형으로 돌린다.
3. 질문에 원문 문장을 붙여 넣지 않는다. 원문과 같은 단어가 많으면 다른 말로 바꾼다 (Kiwi 내용어 겹침을 검수 때 확인).
4. **비교형(2·3유형) 위주로** 쓴다. 템플릿 문항(`data/eval/numeric_auto.jsonl`)이 단일 수치를 이미 많이 덮는다.

예시 (실제 코퍼스·OpenDART로 확인한 것):
1. (3유형) "2024 사업연도에 영업이익을 더 많이 낸 곳은 삼성전자와 SK하이닉스 중 어디이고, 얼마나 차이 나나? (연결)" → 삼성전자 32,725,961백만원 vs SK하이닉스 23,467,319백만원, 차이 9,258,642백만원. 근거 `20250311001085_0086`·`20250311001085_0087`(삼성 요약재무정보, overlap 때문에 같은 행이 두 청크에 있음), `20250319000665_0082`(SK하이닉스 요약재무정보) + OpenDART `dart_OperatingIncomeLoss`.
2. (2유형 서술) "HMM은 2023년 말과 2024년의 컨테이너 운임 상승 원인을 각각 무엇으로 설명했나?" → 2023: 파나마 운하 가뭄, 홍해 사태로 인한 수에즈 운하 우회 / 2024: 홍해 이슈, 미국·캐나다 항만노조 파업 우려, 관세 앞둔 중국발 선적 앞당기기. 근거 `20240328001188_0047`, `20240328001188_0495`, `20250318000828_0045`.
3. (5유형) "삼성전자 경영진이 사업보고서에서 밝힌 2026년 말 목표 주가는?" → 보고서에서 확인할 수 없음 (사업보고서는 목표 주가를 공시하지 않는다). `gold_chunk_ids: []`.

## 5. 검수
### 체크리스트 (문항마다 3개 모두 확인)
1. **질문이 명확한가:** 회사·사업연도·(수치면) 연결/별도가 있는가. 두 가지로 읽히지 않는가.
2. **정답이 하나인가:** 다른 청크나 다른 해석으로 다른 답이 나오지 않는가 (재작성 값은 `answer_alt`로 처리하면 하나로 본다).
3. **근거가 실제로 답을 담는가:** `gold_chunk_ids`의 청크만 읽고 답할 수 있는가. 예비 실험에서 FinDartBench 라벨이 질문과 무관한 문단을 가리킨 경우가 있었다 (기아 "생산능력" 질문의 정답이 사업 개요 문단).

### 판정
| 판정 | 기준 | 처리 |
|---|---|---|
| 통과 | 3개 모두 예 | 그대로 |
| 수정 | 고치면 통과 (연도 누락, 근거 ID 추가 등) | 고친 뒤 `review.history`에 기록 |
| 폐기 | 정답이 없거나 둘 이상, 근거를 못 찾음 | `status: "discarded"`로 남기고 집계에서 뺀다 |

### 30문항 교차 검수와 일치도
- 30문항(유형별 6개, 사람 문항·LLM 문항 섞어서)을 2명이 **서로 보지 않고** 따로 판정한다.
- 일치도는 Cohen's κ (판정 3범주: 통과/수정/폐기):
  - p_o = 두 사람이 같은 판정을 한 비율
  - p_e = Σ_k (A가 k로 판정한 비율 × B가 k로 판정한 비율)
  - κ = (p_o − p_e) / (1 − p_e)
  - 계산: `sklearn.metrics.cohen_kappa_score(a_labels, b_labels)`. 보고할 때 κ와 함께 p_o도 적는다.
- κ ≥ 0.6이면 나머지는 1명이 검수. 그보다 낮으면 불일치 문항을 같이 보며 기준을 고친 뒤 30문항을 새로 뽑아 다시 한다.

## 6. 파일 형식 (`data/eval/*.jsonl`, 한 줄에 한 문항)
| 필드 | 형식 | 설명 |
|---|---|---|
| `qid` | str | 파일 접두어 + 번호 (`num-0001`, `hum-0001`, `llm-0001`) |
| `type` | int 1–5 | 질문 유형 |
| `question` | str | 질문 |
| `corp`, `fiscal_year` | list[str], list[int] | 질문이 가리키는 회사·사업연도 (비교형은 2개) |
| `answer_value`, `answer_alt`, `answer_unit` | float, list[float] 또는 null, "원"/"%" | 수치 정답 |
| `answer_text`, `answer_points` | str, list[str] | 서술 정답 |
| `answer_extra` | dict | 두 값, 증감률, 큰 쪽 회사 등 |
| `gold_chunk_ids` | list[str] | 근거 청크 (5유형은 `[]`) |
| `source` | list[dict] | 수치 출처 (`corp, fiscal_year, rcept_no, account_id, fs_div`) |
| `generated_by` | str | `template` / `llm:<모델명>` (예: `llm:Qwen2.5-7B-Instruct`) / `human:<이니셜>` (예: `human:BG`) |
| `review` | dict | `{"status": "pass"/"revise"/"discarded", "by": "<이니셜>", "history": [...]}` |
| `split` | "dev"/"test"/null | 분할 |
| `notes` | str | 예외 사유 등 |

## 7. 분할 원칙
- **dev 50 / test 150**, 유형별 비율을 두 쪽에서 같게 (유형별로 1:3).
- 사람 문항과 LLM·템플릿 문항도 각 쪽에 같은 비율로. 점수도 따로 보고한다.
- 같은 근거 청크를 공유하는 문항은 같은 쪽에 둔다 (근거 단위로 묶어서 나눈다, T4와 같은 원칙).
- 분할은 seed 42로 한 번 만들어 파일(`data/eval/splits.json`)로 고정한다. 튜닝은 dev로만, test는 마지막에 한 번.
- **미세조정 학습 쌍과 겹치지 않게:** 학습 쌍은 평가 10개사를 뺀 Dartdoc 회사에서만 만든다. 그래서 회사 단위로 이미 분리된다. 평가셋을 만들 때 Dartdoc 청크를 근거로 쓰지 않는다.
