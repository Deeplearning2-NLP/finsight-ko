# 중간 발표(11/20) 계획 — 프로포절 피드백(10/26) 반영

교수님 중간보고 요구: 확정 데이터, 기준선 결과, 직접 학습 모델의 예비 결과 수치. 피드백 5절 체크리스트를 기준으로 한다.

| # | 작업 | 피드백 근거 | 산출물 | 상태 |
|---|---|---|---|---|
| M1 | 학습 질문 형식을 **평가셋과 독립인 기준**으로 다양화 (연도 포함/생략/상대 표현, 회사명/별칭, 수치/서술 비율을 평가셋을 보기 전에 고정) → 5,000쌍 재생성 | 부족한 점 2, 보완 1 | `pairs_m1.jsonl`, 형식 분포 표 | ⬜ |
| M2 | 학습 쌍 200개 사람 검수 (잘못된 쌍 비율) | 보완 1 | 검수표 | ⬜ (사람) |
| M3 | hard negative 비율·종류를 dev에서 비교 (in-batch만 / 연도 neg 25·50·100% / 다른 섹션 neg) | 보완 2 | dev 표 | ⬜ |
| M4 | 공개 KURE vs fine-tuning, **유형별 + 짝지은 비교**(McNemar·클러스터 부트스트랩) | 보완 3, 체크 2 | test 표 (1회) | ⬜ |
| M5 | 회사·연도 혼동률 변화 + 남은 오류 30건 유형 | 체크 3 | 오류표 | ⬜ |
| M6 | **재정렬 모델(cross-encoder) 학습** — fine-tuning 효과가 없을 때의 직접 학습 모델 | 부족한 점 1, 체크 4 | dev/test 표 | ⬜ |
| M7 | 자체 평가셋 200문항 (Dev 50/Test 150, 유형별 개수, 사람 작성 비율, κ) | 체크 1 | `data/eval/` | ⬜ (팀) |
| M8 | 모든 표 제목에 코퍼스·문항 수 명시, 쪽마다 핵심 숫자 1개 | 부족한 점 3·4 | 결과 문서 | ⬜ |

실행 규칙: 모든 학습·평가는 `tmux` 세션에서 로그를 파일로 남기며 돌린다(VPN 끊김 대비). 설정은 dev로, test는 마지막 1회. 데이터·체크포인트 커밋 금지.
