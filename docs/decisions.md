## 2026-10-21 학습 쌍 출처 변경, 질문 메타데이터 추출
- **학습 쌍은 Dartdoc이 아니라 평가 대상이 아닌 회사의 OpenDART 원문으로 만든다.** 이유: Q6 파일럿에서 Dartdoc 기반 쌍의 사용 가능 비율 43%, 오류 12/30 중 9건이 표 숫자 누락(숫자 지어내기 포함). 원문은 평가 코퍼스와 같은 파서로 표 숫자가 살아 있다. 학습 회사(Q6의 20개사)와 평가 10개사는 계속 분리.
- Dartdoc은 회사 선정·통계 용도로만 남긴다.
- **질문 메타데이터 추출 모듈:** 질문에서 회사명과 사업연도를 규칙 기반으로 뽑아(예: "2024 사업연도", "2024년", "제56기", "당기/전기", 회사 별칭) 검색 필터로 쓴다. Q3 오라클(R@1 0.674)과 비교해 실제 효과를 잰다. 한국어 전처리 기여로 보고.
- 발표에서 주장하는 개선은 클러스터 부트스트랩 CI가 0을 넘는 것만: 미세조정 > 공개 KURE (R@5·MRR), RRF > 미세조정 단독 (R@5). R@1 차이와 "미세조정 > 형태소 BM25"는 아직 주장하지 않는다.

## 2026-10-20 재작성(restatement) 값 처리, 학습 쌍 생성 LLM
- **단일 수치:** 그 사업연도 보고서의 값(처음 보고된 값)이 정답.
- **연도 비교:** 나중 사업연도 보고서의 당기·전기 쌍이 기본 정답(같은 보고서, 같은 회계 기준으로 회사가 직접 비교한 값). 증감액·증감률도 이 쌍으로 계산.
- **채점:** 처음 보고된 값과 재작성 값 중 하나와 허용 오차(0.5%) 안에서 일치하면 정답. 정답이 두 개인 문항은 `answer_alt`로 저장하고, 보고서에 "재작성 문항 수와 그 문항만의 점수"를 따로 적는다.
- 이유: 비교 질문의 의미(같은 기준으로 비교)에 맞고, 재작성 때문에 억울하게 틀리는 경우를 없앤다. 해당 문항이 적어(111칸 중 8칸) 결과에 주는 영향이 작고, 투명하게 공개할 수 있다.
- **학습 쌍 생성 LLM:** 서버의 오픈 모델(Qwen 계열 7–8B instruct, vLLM)로 생성. 시스템(답변) LLM은 다른 계열(EXAONE 등)로 해서 "생성 LLM ≠ 시스템 LLM"을 지킨다. 상용 API는 쓰지 않는다(비용 0, 재현 가능).

## 2026-10-20 범위 확정 (안 A)
- 평가: FinDartBench 10개사 × 사업연도 2022–2024 사업보고서 30건, OpenDART 원문 파싱(표 포함)을 평가 코퍼스로. 이유: Dartdoc에는 이 중 7개사의 2022–2023 보고서가 없고, 표 숫자가 빠져 있음.
- 학습: Dartdoc에서 평가 10개사를 뺀 회사(3년 모두 있는 약 750개사) 청크로 LLM 질문을 만들어 미세조정 학습 쌍 생성 → 학습·평가 회사 분리.
- FinDartBench 기반 검색 결과(코퍼스 195문단)와 T6 미세조정 스모크(학습·테스트 같은 회사)는 **예비 결과**로만 쓴다. 결론은 원문 코퍼스 + 자체 평가셋으로.
- 답 없는 질문은 "범위 밖이지만 실제로는 공시된 정보"(예: FY2025)가 아니라 "사업보고서에 원래 없는 정보"로 만든다.
