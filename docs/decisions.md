## 2026-11-17 중간 발표 실험 설계 (프로포절 피드백 10/26 반영)
- **학습 질문 형식은 평가셋과 독립인 기준으로, 생성 전에 고정한다** (순환 구조 방지): 연도 명시 40% / 생략 45% / 상대 표현 15%, 회사명 55% / 별칭 15% / 생략 30%, 값 있는 표 청크에서만 숫자 질문 50%. 이 비율은 튜닝하지 않는다 (`scripts/m1_chunks.py`).
- **hard negative는 질문 형식에 맞춘다:** 연도가 있는 질문에만 "다른 사업연도" negative를 쓴다(연도 없는 질문에는 다른 연도 문단도 정답이기 때문). 비교 변형 5개(in-batch / easy / hard / hard 50% / 다른 섹션)는 **dev의 dense MRR@10**으로 하나만 고른다.
- **재정렬 모델(cross-encoder)을 함께 학습한다** (fine-tuning 효과가 없을 때의 직접 학습 모델): klue/roberta-base(직접 학습)와 bge-reranker-v2-m3(공개 재정렬기 미세조정), 공개 재정렬기 zero-shot을 dev MRR@10으로 비교.
- 팀 자체 평가셋(200문항)이 아직 없으므로 이번 비교는 지금까지와 같은 FinDartBench 기반(원문 34,427청크, test 1,947문항)으로 한다. 자체 평가셋이 들어오면 `scripts/eval_m.py`로 같은 비교를 다시 한다. 모든 표 제목에 코퍼스·문항 수를 적는다.
- 학습 쌍 200개는 사람이 검수한다(`outputs/midterm/pairs_m1_review_200.md`). 검수 전 결과는 그렇게 표시한다.
- **결과 후 (같은 날):** dev 선택은 M3 hard, 재정렬기 bge-zero. test에서는 재정렬기 3개 모두 유의하게 좋았지만 dev에서는 효과가 거의 없었다(dev 근거 문맥 22개). **test를 보고 선택을 바꾸지 않는다.** 재정렬기는 검수된 자체 평가셋 dev로 다시 고른다. 발표 주장: "미세조정 임베딩은 전체로 공개 KURE와 유의차 없음, 연도·회사가 있는 질문에서만 유의한 이득. 직접 학습한 KLUE 재정렬기는 유의한 이득(+4.2%p)." (`docs/midterm-report.md`)

## 2026-10-21 학습 쌍 출처 변경, 질문 메타데이터 추출
- **학습 쌍은 Dartdoc이 아니라 평가 대상이 아닌 회사의 OpenDART 원문으로 만든다.** 이유: Q6 파일럿에서 Dartdoc 기반 쌍의 사용 가능 비율 43%, 오류 12/30 중 9건이 표 숫자 누락(숫자 지어내기 포함). 원문은 평가 코퍼스와 같은 파서로 표 숫자가 살아 있다. 학습 회사(Q6의 20개사)와 평가 10개사는 계속 분리.
- Dartdoc은 회사 선정·통계 용도로만 남긴다.
- **질문 메타데이터 추출 모듈:** 질문에서 회사명과 사업연도를 규칙 기반으로 뽑아(예: "2024 사업연도", "2024년", "제56기", "당기/전기", 회사 별칭) 검색 필터로 쓴다. Q3 오라클(R@1 0.674)과 비교해 실제 효과를 잰다. 한국어 전처리 기여로 보고.
- 발표에서 주장하는 개선은 클러스터 부트스트랩 CI가 0을 넘는 것만: 미세조정 > 공개 KURE (R@5·MRR), RRF > 미세조정 단독 (R@5). R@1 차이와 "미세조정 > 형태소 BM25"는 아직 주장하지 않는다.

## 2026-10-20 재작성(restatement) 값 처리, 학습 쌍 생성 LLM
- **단일 수치:** 그 사업연도 보고서의 값(처음 보고된 값)이 정답.
- **연도 비교:** 나중 사업연도 보고서의 당기·전기 쌍이 기본 정답(같은 보고서, 같은 회계 기준으로 회사가 직접 비교한 값). 증감액·증감률도 이 쌍으로 계산.
- **채점:** 처음 보고된 값과 재작성 값 중 하나와 허용 오차(0.5%) 안에서 일치하면 정답. 정답이 두 개인 문항은 `answer_alt`로 저장하고, 보고서에 "재작성 문항 수와 그 문항만의 점수"를 따로 적는다.
- 이유: 비교 질문의 의미(같은 기준으로 비교)에 맞고, 재작성 때문에 억울하게 틀리는 경우를 없앤다. 해당 문항이 적어(111칸 중 8칸) 결과에 주는 영향이 작고, 투명하게 공개할 수 있다.
- **학습 쌍 생성 LLM:** 서버의 오픈 모델(Qwen 계열 7–8B instruct, vLLM)로 생성. 시스템(답변) LLM은 다른 계열(EXAONE 등)로 해서 "생성 LLM ≠ 시스템 LLM"을 지킨다. 상용 API는 쓰지 않는다(비용 0, 재현 가능).
