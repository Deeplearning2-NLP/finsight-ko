## 2026-11-19 수치 검증 실험 설계 (대표 실험 2, 실행 전 고정)
- **질문:** 자체 평가셋 v1의 수치 문항(유형 1–3) + 답 없는 질문(유형 5). 프롬프트·형식 수정은 dev로만, test는 한 번 (수치 문항은 test 검색 평가에 이미 두 번 쓰였지만 **답변 실험으로는 처음**).
- **답변 LLM = EXAONE-3.5-7.8B-Instruct** (vLLM, greedy, 로컬). 학습 쌍 생성(Qwen2.5-7B)·평가셋 생성(EEVE-10.8B)과 다른 계열. 라이선스는 비상업 연구용이라 수업 프로젝트에 쓴다.
- **세 시스템**
  - S0 LLM 단독: 질문만 준다.
  - S1 RAG: v2 최종 검색 top-5 청크를 주고 그 안에서만 답하게 한다.
  - S2 RAG + OpenDART: LLM이 질문을 조회 계획(회사·사업연도·계정 6개 중 하나·연산 value/change/compare)으로 바꾼다. Python이 OpenDART 캐시(`financials_a.csv`, `fnlttSinglAcntAll` 연결 기준)에서 값을 찾아 계산하고, LLM은 그 값과 top-5 청크로 설명만 쓴다. 채점하는 핵심 수치는 Python 계산값이다. 계획이 "조회 불가"면 S1 답을 쓴다.
- **지표**
  - Numeric Claim Accuracy: 핵심 수치(단일=값, 연도 비교=증감액, 기업 비교=차이)가 `answer_value`나 `answer_alt`와 0.5% 안에서 일치하는 비율. 모름(null)은 오답으로 친다.
  - Coverage: null이 아닌 답의 비율.
  - Unsupported Claim Rate: 답변 문장 속 금액 중 시스템이 받은 근거(청크 숫자 × 표 단위, 조회·계산값)와 0.5% 안에서 맞는 것이 없는 비율. S0은 근거가 없어 정의상 해당 없음.
  - 답 없는 질문의 거절률.
  - 재작성 문항만의 점수를 따로 적는다.
- 비교: S1 vs S0, S2 vs S1 McNemar + 문항 부트스트랩.
- 코드: `scripts/numeric_qa.py`.
- **dev에서 고친 것 (test 전):**
  - key_value를 숫자만 적은 경우(원 단위) 파싱 누락을 고쳤다.
  - S2 연산은 회사 수·연도 수로 정하고 LLM의 연산 표시는 참고만 한다. dev 오답 2건이 "한 회사 두 연도"를 compare로 표시한 경우였다.
  - 국민은행 FY2022 빈 값(013)을 건너뛰게 했다.

## 2026-11-19 성능 개선 v2 (dev 실행 전 고정한 선택 규칙)
- **test 사용 이력 공개:** v1 test(147)는 11/18에 한 번 썼다. 그때 본 약점(기업 비교형 R@5 0.20, "N 사업보고서" 연도 누락)이 이번 개선의 동기다. 그래서 v2 test 결과는 "test를 이미 본 뒤의 두 번째 사용"이라고 표시한다. 선택 자체는 아래처럼 dev로만 한다.
- 기준 설정 = v1 최종 (M3 hard + Kiwi BM25 RRF + 필터 + bge-ft, 후보 20). 단계마다 한 요소만 바꾸고, **기준보다 0.01 넘게 좋아야** 바꾼다 (아니면 기준 유지).
  - A. "N 사업보고서" 해석 (v1 dev MRR@10): 없음 / 사업연도 N / 접수연도 N(→ 사업연도 N−1) / 둘 다.
  - B. 회사가 2개 이상인 질문 분해 (v1 dev **두 회사 모두 top-5 포함 비율**, 단 전체 MRR@10이 0.01 넘게 떨어지면 기각): 끔 / 회사별 필터로 같은 질문 검색 후 번갈아 합치기 / 다른 회사 이름을 지운 하위 질문으로 검색 후 번갈아 합치기.
  - C. 재정렬 후보 수 (v1 dev MRR@10): 20 / 40.
  - D. 재정렬기 (v1 dev MRR@10): bge-ft / klue-ft / bge-mined / klue-mined (retriever로 뽑은 학습 코퍼스 hard negative를 추가해 다시 학습, `scripts/mine_negatives_m.py`).
  - E. 연도 없는 질문 (FinDartBench dev MRR@10, 자체 평가셋에는 연도 없는 질문이 없음): 규칙 없음 / 최신 사업연도(2024)로 필터 / 최신 연도 필터 결과와 원래 결과를 RRF로 합치기.
- **B 변형 추가 (dev 1차 결과를 본 뒤):** dev 1차에서 B의 두 변형 모두 효과가 없었다(두 회사 포함 0.25 그대로). dev 문항을 보니 이름만 지운 하위 질문이 "…와 기아 중 어느 회사의…"처럼 여전히 비교 문장이라 기아 재무 표를 못 찾았다. 그래서 규칙 기반 하위 질문 "회사의 N 사업연도 연결 기준 계정은 얼마인가?"(서술형은 회사명·비교어를 지우고 회사명을 앞에 붙임)를 B 후보에 추가하고 dev 단계 전체를 다시 돌렸다. test는 아직 쓰지 않았다.
- 그 뒤 v1 test와 FinDartBench test를 한 번씩 돌린다 (`scripts/eval_v2.py`).
- **결과 (같은 날):** A 사업연도 N, B 템플릿 분해, C 후보 40, D bge-ft 유지(mined 재학습은 dev에서 나빠 버림), E 최신 사업연도. `finsight.query_meta.REPORT_RULE = "fiscal"`을 기본값으로 바꿨다. v1 test R@5 0.657 → 0.888, FinDartBench test R@1 0.399 → 0.592 (`docs/midterm-report.md` 14절). FinDartBench의 이득은 "연도 없는 질문의 정답이 대부분 2024"라는 데이터셋 성질에 기댄다 → 답변 단계에서 "최신 보고서 기준" 문구를 붙인다.

## 2026-10-20 재작성(restatement) 값 처리, 학습 쌍 생성 LLM
- **단일 수치:** 그 사업연도 보고서의 값(처음 보고된 값)이 정답.
- **연도 비교:** 나중 사업연도 보고서의 당기·전기 쌍이 기본 정답(같은 보고서, 같은 회계 기준으로 회사가 직접 비교한 값). 증감액·증감률도 이 쌍으로 계산.
- **채점:** 처음 보고된 값과 재작성 값 중 하나와 허용 오차(0.5%) 안에서 일치하면 정답. 정답이 두 개인 문항은 `answer_alt`로 저장하고, 보고서에 "재작성 문항 수와 그 문항만의 점수"를 따로 적는다.
- 이유: 비교 질문의 의미(같은 기준으로 비교)에 맞고, 재작성 때문에 억울하게 틀리는 경우를 없앤다. 해당 문항이 적어(111칸 중 8칸) 결과에 주는 영향이 작고, 투명하게 공개할 수 있다.
- **학습 쌍 생성 LLM:** 서버의 오픈 모델(Qwen 계열 7–8B instruct, vLLM)로 생성. 시스템(답변) LLM은 다른 계열(EXAONE 등)로 해서 "생성 LLM ≠ 시스템 LLM"을 지킨다. 상용 API는 쓰지 않는다(비용 0, 재현 가능).
