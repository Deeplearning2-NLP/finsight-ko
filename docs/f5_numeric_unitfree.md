# F5. 수치 검증 보조 채점: 단위 무시 vs ±0.5% (분석만)

`scripts/numeric_qa_unitfree.py`. `numeric_qa.py`가 저장한 핵심 수치를 그대로 다시 채점했다(새 생성 없음). **단위 무시** = 10^k배(k = −12…12) 차이를 허용하고 ±0.5% 안이면 정답. RAG 오답이 단위·자릿수 문제인지 숫자 자체 문제인지 나누려는 것이다. 숫자는 저장된 출력에서만 가져왔다.

**자체 평가셋 v1 test, 수치 96문항 (EXAONE-3.5-7.8B, greedy)**

| 시스템 | 답함 | 정답 ±0.5% | 정답 단위 무시 | 자릿수만 틀림 | 숫자 자체가 틀림 |
|---|---|---|---|---|---|
| S0 LLM 단독 | 11 | 0/96 = 0.0% | 0/96 = 0.0% | 0 | 11 |
| S1 RAG | 53 | 4/96 = 4.2% | 28/96 = 29.2% | 24 | 25 |
| S2 RAG + OpenDART | 95 | 92/96 = 95.8% | 93/96 = 96.9% | 1 | 2 |

| 시스템 | 단일 수치 (±0.5% → 단위 무시) | 연도 비교 | 기업 비교 |
|---|---|---|---|
| S0 LLM 단독 | 0/29 → 0/29 | 0/31 → 0/31 | 0/36 → 0/36 |
| S1 RAG | 4/29 → 19/29 | 0/31 → 9/31 | 0/36 → 0/36 |
| S2 RAG + OpenDART | 26/29 → 27/29 | 31/31 → 31/31 | 35/36 → 35/36 |

**자체 평가셋 v1 dev, 수치 26문항 (EXAONE-3.5-7.8B, greedy)**

| 시스템 | 답함 | 정답 ±0.5% | 정답 단위 무시 | 자릿수만 틀림 | 숫자 자체가 틀림 |
|---|---|---|---|---|---|
| S0 LLM 단독 | 1 | 0/26 = 0.0% | 0/26 = 0.0% | 0 | 1 |
| S1 RAG | 17 | 5/26 = 19.2% | 9/26 = 34.6% | 4 | 8 |
| S2 RAG + OpenDART | 26 | 26/26 = 100.0% | 26/26 = 100.0% | 0 | 0 |

| 시스템 | 단일 수치 (±0.5% → 단위 무시) | 연도 비교 | 기업 비교 |
|---|---|---|---|
| S0 LLM 단독 | 0/11 → 0/11 | 0/9 → 0/9 | 0/6 → 0/6 |
| S1 RAG | 5/11 → 8/11 | 0/9 → 1/9 | 0/6 → 0/6 |
| S2 RAG + OpenDART | 11/11 → 11/11 | 9/9 → 9/9 | 6/6 → 6/6 |

**해석 (test)**

- RAG가 답한 53개 중 4개만 맞았다. 24개는 자릿수만 틀렸고(단위 무시로 맞음), 25개는 숫자 자체가 틀렸다. 즉 RAG 오답은 표 단위를 반영하지 않은 것과, 증감·차이 계산 또는 다른 셀을 읽은 것이 섞여 있다.
- 보고서 15절의 "단위 오류 29건"(정답 대비 비율을 10의 거듭제곱으로 어림한 분류)과 숫자가 다르다. 이 표는 answer_alt와 부호까지 맞춰 정확히 다시 판정한 값이라, 이쪽을 쓴다.
- 단위 문제를 빼고 봐도 RAG(S1)는 OpenDART 조회(S2)에 크게 못 미친다. 특히 계산이 필요한 연도 비교·기업 비교에서 그렇다(유형별 표).
- **주의:** S2 정답률 95.8%는 문항이 모두 OpenDART 6개 계정(매출·영업이익·순이익·자산·부채·자본)의 템플릿형 수치라서, 조회기가 다루는 범위와 정확히 겹치는 쉬운 조건이다. 6개 계정 밖의 수치나 주석·본문 숫자는 S2가 조회하지 못한다("조회 불가" → RAG 답 사용).
