# 질문 유형표 (평가셋 설계)

평가셋 약 200문항 = 5유형 × 약 40 (dev 50 / test 150). 예시는 모두 실제 데이터에서 값·근거를 확인한 것이다 (2026-10-20).
- 수치 값: OpenDART `fnlttSinglAcntAll` (연결 CFS, 사업보고서 `11011`, `bsns_year=2024`, 당기 `thstrm_amount` / 전기 `frmtrm_amount`), 단위 원.
- 근거 청크 ID 표기: Dartdoc는 `rcept_no/섹션/chunk`, 원문 파싱은 `rcept_no`.
- 🖊 표시 = 사람이 다듬을 문항 (비교형 위주, 최종 평가셋의 약 30%는 사람 작성).
- 투자 권유 아님.

| 유형 | 정의 | 정답 형태 | 평가 방법 |
|---|---|---|---|
| 1. 단일 수치 | 한 회사·한 사업연도의 재무 계정 1개 | 숫자 + 단위 (원으로 정규화) | OpenDART 값과 `numbers.rel_close` (허용 0.5%) → Numeric Claim Accuracy, Coverage |
| 2. 연도 비교 | 같은 회사의 두 사업연도 비교 (수치 증감 또는 서술 변화) | 두 값 + 증감(액·률) 또는 변화 요약 | 수치: 두 값·증감 모두 맞아야 정답 (Python 계산) / 서술: 사람 평가 + 근거 청크 Recall@k |
| 3. 기업 비교 | 같은 업종 두 회사의 공통 계정 비교 | 두 값 + 대소·차이 | 두 값 + 비교 결론 정답. 계정명이 다르면(`영업이익` vs `영업이익(손실)`) 공통 계정으로 매핑 |
| 4. 서술 요약 | 사업의 내용·위험 요인·시장 상황 요약 | 2–4문장 요약 + 근거 청크 | 근거 청크 Recall@5 / MRR@10 + 사람 평가 (LLM judge 쓰면 30문항 사람 채점과 일치도) |
| 5. 답 없는 질문 | 사업보고서에 없는 정보 (미래 주가, 공시 범위 밖, 존재하지 않는 연도) | "보고서에서 확인할 수 없음" | 거절 정확도 (답하면 오답), Unsupported Claim Rate |

## 문항 작성 규칙 (요약)
- 질문에 회사명·사업연도·연결/별도를 명시 (단, 5유형은 일부러 범위 밖).
- 사업연도는 보고서명 `(YYYY.MM)` 기준, 정정공시는 최신본만.
- 수치 정답은 OpenDART 값, 서술 정답은 근거 청크 ID를 1개 이상.
- 같은 문단이 여러 청크에 중복되면(예: HMM II/8 = IV/1) 모두 정답 ID로.
- 평가셋 기업-연도는 미세조정 학습 쌍과 겹치지 않게 (`outputs/proposal/splits.json` 원칙과 같음).
