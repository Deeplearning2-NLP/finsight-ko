2. 질문에서 회사·사업연도를 뽑아 검색 필터로 쓰는 **질문 메타데이터 추출 모듈**을 만든다 (Q3 오라클 R@1 0.674).

공통 규칙: 결과는 `docs/proposal-results.md`에 **"11. R1–R3"** 절, `docs/feedback-response.md`·`docs/data.md` 갱신, 데이터·키 커밋 금지, 설정은 dev로만 고르고 test는 마지막에 한 번. **슬라이드는 만들거나 고치지 않는다.** R1·R2가 우선, R3는 시간이 남으면.

## R1. 질문 메타데이터 추출 모듈 (한국어 전처리)
`src/finsight/query_meta.py` + 테스트:
- **회사:** 평가 10개사의 공식명·별칭 사전 (예: 현대차·현대자동차, KB국민은행·국민은행, 한전·한국전력공사, SKT·SK텔레콤, 하이닉스). 형태소 분석으로 조사 붙은 형태("현대차의", "기아는")도 처리.
- **사업연도:** "2024 사업연도", "2024년", "FY2024", "24년", "제56기"(회사별 기수 → 사업연도 표는 원문 보고서 표지·`list.json`에서 만든다), "당기/전기/전전기"(기준 보고서가 정해질 때만), "작년·올해" 같은 상대 표현은 기준 시점이 없으므로 **추출하지 않고 기록만**. 연도가 여러 개면 모두 반환(비교 질문).
- 출력: `{"companies": [...], "fiscal_years": [...], "confidence": ..., "spans": [...]}`.
- **평가 1 (추출 정확도):** FinDartBench dev 문항에서 무작위 100개를 직접 라벨(회사, 사업연도, 연도 언급 없음) → 추출 precision/recall. 연도가 질문에 명시된 비율도 함께 보고.
- **평가 2 (검색 효과):** P4/Q3와 같은 조건에서 RRF + 추출한 필터. 연도가 안 뽑히면 회사 필터만, 회사도 안 뽑히면 필터 없음(폴백). test R@1/R@5/MRR을 "필터 없음 0.298 / 오라클 0.674"와 나란히. 연도가 명시된 문항과 아닌 문항으로 나눠서도.
- 잘못 뽑은 경우(틀린 연도로 필터 → 정답이 범위 밖)가 몇 건인지 따로 센다.

## R2. 학습용 원문 코퍼스 + 학습 쌍 재파일럿
- Q6에서 고른 20개사(평가 10개사와 겹치지 않음 재확인) × 사업연도 2022–2024 사업보고서 원문 60건을 `build_corpus.py`로 수집·파싱·청킹 (같은 섹션 누락 검사). 호출은 캐시, 일 한도 확인.
- 출력: `data/processed/corpus_train.jsonl` + 통계(회사 × 연도 청크 수, 표 청크 비율).
- Q6 생성 스크립트를 원문 청크로 다시 실행 (같은 Qwen 모델·프롬프트 기반), Q6 교훈 반영:
  - 숫자 질문은 **값이 있는 표 청크**에서만, 생성된 숫자가 청크에 실제로 있는지 `finsight.numbers`로 자동 검사
  - 회사명·사업연도 누락 질문 자동 제거 (R1 모듈로 검사)
  - hard negative = 같은 회사·같은 섹션의 **다른 사업연도** 청크 중 positive와 너무 비슷한 것(5-gram Jaccard ≥ 0.8 또는 답이 그대로 있는 것)은 제외
  - 원문 문장 베끼기 비율(Kiwi 내용어 Jaccard) 분포
- 300쌍 재생성 → 무작위 30쌍 직접 판정(답 가능 / 베끼기 / 모호 / 오류). **Q6(43%)과 나란히 비교.** 필터 전후 남는 쌍 수.
- 품질이 70% 이상이면 본 생성 규모 추정(목표 수천 쌍에 필요한 청크 수·GPU 시간)까지. 본 학습은 하지 않는다.
