## 4. 보고서 1개 파싱·청킹, 표 포함 (T3, 꼭 할 일 4번 전반)
`scripts/opendart_parse_one.py`, 대상: 삼성전자 사업보고서 (2024.12), rcept_no 20250311001085 (`corpCode.xml` → corp_code 00126380 → `list.json` → `document.xml`).

- 원문 ZIP 안의 XML 3개 (본문 6.3MB + 첨부 2개). 목차는 `SECTION-1/2/3` + `TITLE`로 나뉜다. 본문은 `P`, 표는 `TABLE/TR/TD·TH·TE·TU`.
- 파싱 결과: 본문 블록 2,070개, 표 1,052개. II 사업의 내용: 본문 145블록(26,203자) + 표 60개 / IV 경영진단: 본문 48블록(10,835자) + 표 19개.
- 처리한 함정:
  - 단위는 표 바로 앞의 1행짜리 표 "(단위 : 백만원)"에 들어 있다. 표 안에 있는 "(단위 : 원)"(주당이익 행 주석)을 단위로 잡으면 값이 100만 배 틀어진다 → 바로 앞 단위 표를 우선 적용.
  - 재무제표 주석은 "표 안에 본문과 표가 다시 들어 있는" 레이아웃 표다 → 중첩 표·긴 셀은 본문으로 풀어 처리.
  - `ROWSPAN`/`COLSPAN`은 격자로 펼친다.

- 주의:
  - 질문 1,993개가 문단 71개를 공유해서 질문끼리 독립이 아니다 → p값은 낙관적으로 봐야 한다.

- 본 실험 계획: Dartdoc·원문 청크에서 LLM으로 질문을 만들어(생성 LLM ≠ 시스템 LLM, 검수 비율 기록) 수천 쌍을 만들고, **같은 회사 다른 사업연도 문단을 hard negative로**, 평가 회사·기업-연도와 겹치지 않게 다시 학습한다. 비교는 자체 평가셋으로.

- **관대한 지표는 거의 오르지 않는다** (R@1 +0.005–0.009). 정답 청크 460개 중 다른 연도에 거의 같은 청크(Jaccard ≥ 0.9)가 있는 것은 19개뿐이다. 즉 연도 혼동은 "같은 문단을 해마다 복사"해서가 아니라 "같은 섹션의, 숫자·문장이 조금씩 다른 문단"끼리 헷갈려서 생긴다. → 문자열 중복 제거로는 해결되지 않고, **같은 회사·같은 섹션의 다른 연도 청크를 hard negative로 학습**해야 연도 구분 능력이 생긴다는 근거.
- 필터를 걸어도 순서(미세조정 > 공개 KURE, RRF 최고)는 그대로다.

- 9주차 본 생성에 반영할 것:
  1. 원천 청크를 Dartdoc 대신 **같은 20개사(또는 750개사 일부)의 OpenDART 원문**으로 바꿔 표 숫자를 살리거나, Dartdoc을 쓰면 숫자 질문 요구를 빼고 숫자가 빠진 청크를 거른다.
  2. 생성 후 자동 필터(답 없음 / 숫자 불일치 / 회사·연도 누락 / 지시어).
  3. hard negative는 positive와의 Jaccard가 높으면(≥ 0.5) 건너뛰고 다음 후보를 쓴다.
  4. 필터 후 100쌍을 사람이 다시 판정해 합격률을 기록한다.

### 10.7 고전 기준선 TF-IDF (Q7)
TF-IDF(Kiwi 내용어, sklearn 기본 설정, 튜닝 없음) 코사인: test R@1 0.171 / R@5 0.433 / MRR 0.282. **공백 BM25(0.445)보다도 낮고 Kiwi BM25(0.615)보다 18%p 낮다.** 같은 토큰을 쓰는데도 이만큼 차이가 나는 것은 BM25의 단어 빈도 포화(k1)와 문서 길이 정규화(b) 때문으로 보인다. 가설: 항목명이 여러 번 반복되는 표 청크(코퍼스의 87%)가 TF-IDF에서 과대평가된다. 확인하지는 않았다. 모델 단계 표의 "고전 기준선"은 BM25로 두고, TF-IDF는 참고 행으로 둔다.

- **선택 과정을 밝혀 둔다.** 처음 실행에서는 "연도만이면 연도 필터"가 dev로 선택됐고(test R@1 0.351, 잘못된 필터 36), 그 결과를 중간 보고했다. 이어서 **test의 잘못된 필터 36건을 읽고** "질문 속 연도는 사건 연도인데, 그 내용은 다음 해 보고서에 실린다"는 유형을 찾았다. 34건이 이 유형이었다. 예: "SK텔레콤이 2023년 9월 발표한 AI 피라미드 전략" → FY2024 보고서, "제79기(FY2022) 기아의 연구개발 과제" → FY2023 보고서의 연구개발 실적 표.
- 이 생각에서 "연도 창 y·y+1" 변형을 추가했다. 같은 유형이 dev의 잘못된 필터 13건 중 9건에도 있는 것을 확인한 뒤, **dev MRR로만 골랐다**(0.612 vs 0.610). dev 차이는 아주 작고 dev R@1은 오히려 0.484 vs 0.490으로 낮다. 따라서 "연도 창이 더 낫다"는 주장은 하지 않고, **잘못된 필터를 36 → 6건으로 줄이는 안전장치**로만 보고한다.
