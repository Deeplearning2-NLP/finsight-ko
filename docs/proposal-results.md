## 4. 보고서 1개 파싱·청킹, 표 포함 (T3, 꼭 할 일 4번 전반)
`scripts/opendart_parse_one.py`, 대상: 삼성전자 사업보고서 (2024.12), rcept_no 20250311001085 (`corpCode.xml` → corp_code 00126380 → `list.json` → `document.xml`).

- 원문 ZIP 안의 XML 3개 (본문 6.3MB + 첨부 2개). 목차는 `SECTION-1/2/3` + `TITLE`로 나뉜다. 본문은 `P`, 표는 `TABLE/TR/TD·TH·TE·TU`.
- 파싱 결과: 본문 블록 2,070개, 표 1,052개. II 사업의 내용: 본문 145블록(26,203자) + 표 60개 / IV 경영진단: 본문 48블록(10,835자) + 표 19개.
- 처리한 함정:
  - 단위는 표 바로 앞의 1행짜리 표 "(단위 : 백만원)"에 들어 있다. 표 안에 있는 "(단위 : 원)"(주당이익 행 주석)을 단위로 잡으면 값이 100만 배 틀어진다 → 바로 앞 단위 표를 우선 적용.
  - 재무제표 주석은 "표 안에 본문과 표가 다시 들어 있는" 레이아웃 표다 → 중첩 표·긴 셀은 본문으로 풀어 처리.
  - `ROWSPAN`/`COLSPAN`은 격자로 펼친다.

- FinDartBench 사업보고서 문항 5,638개, 고유 근거 문단(context) 195개, doc_id 486개.
- **분할 단위:** doc_id 하나가 문단 여러 개를 가리키거나 문단 하나를 doc_id 여러 개가 공유하는 경우가 있어서, doc_id만으로 나누면 같은 문단이 train과 test에 동시에 들어간다. 그래서 doc_id와 문단을 연결 성분으로 묶고, 묶음 단위로 회사별 55/15/30% 분할 (seed 42). 문단·doc_id 모두 분할 사이에 겹침이 없는지 코드에서 확인(assert)했다.
  - train 2,936문항 / 99문단 / doc_id 253 · dev 709 / 25 / 63 · test 1,993 / 71 / 170
- 코퍼스: 문단 195개 전체(학습·검증 문단도 방해 문서로 포함)를 KURE 토큰 기준 512 이하로 다시 나눔 → 784청크. 문단 점수는 그 문단의 청크 점수 중 최댓값(MaxP).
- 질문의 정답 = 자기 문단. 하이브리드에 쓸 모델은 **dev MRR로 선택**했고 test로는 아무것도 고르지 않았다.

읽는 법:
- **한국어 전처리 효과:** 공백 → Kiwi 내용어로 바꾸면 R@1 +20.5%p, R@5 +21.7%p (AutoRAG 파일럿의 0.667→0.851과 같은 방향).
- **잘림의 비용:** 근거 문단 88%가 512토큰을 넘는다. 자르면 dense R@1이 0.15–0.21 떨어진다 (KURE 0.642→0.434). 청킹(MaxP)은 꼭 필요하다.
- **공개 임베딩은 형태소 BM25를 넘지 못했다** (KURE-v1 0.642 < BM25 0.658). 이 점이 공시 도메인 미세조정의 동기다. 단, FinDartBench 질문은 LLM이 문단을 보고 만들어서 단어가 겹치기 쉬우므로 **BM25에 유리한 쪽으로 치우쳤을 수 있다** → 본 평가는 사람이 쓴 문항을 섞은 자체 평가셋으로.
- 코퍼스가 작다 (문단 195개, 청크 784개). 본 실험에서는 대상 기업 전체 보고서 청크로 키워야 한다.
- GPU 최대 메모리 (인코딩, 배치 32): mE5-base 1.6GB, bge-m3·KURE-v1 2.9GB.

## 7. 미세조정 스모크 테스트 (T6) — "직접 학습한 모델이 실제로 돈다"
`scripts/train_embedding_smoke.py` → `outputs/proposal/kure-v1-findart-smoke/` (체크포인트 1개, 2.2GB), `t6_train_meta.json`, `retrieval_results_t6.json`, `t6_mcnemar.json`.

- 학습 데이터: **train 분할만** 사용 (2,936문항, 문단 99개 → 512토큰 청크 400개). dev·test 문단은 학습에 쓰지 않았다.
  - 질문 = anchor, 정답 문단 안에서 BM25(Kiwi 내용어) 점수가 가장 높은 청크 = positive, **같은 회사 다른 문단**에서 점수가 가장 높은 청크 = hard negative
- 모델·손실: `nlpai-lab/KURE-v1` (XLM-R large 계열 568M), CachedMultipleNegativesRankingLoss (배치 내 negative + hard negative), 배치 32 (mini-batch 8), lr 1e-5, warmup 10%, 1 epoch = 92 step, max_seq_length 512, bf16, seed 42. 같은 문단을 공유하는 질문이 많아서 한 배치에 같은 positive가 두 번 들어가지 않게 했다 (NO_DUPLICATES).
- 비용: RTX 4090 1장, **학습 127초, GPU 최대 13.2GB.** loss 0.94 → 0.31.
- 하이퍼파라미터는 한 번만 정했고 튜닝하지 않았다 (test로 고른 것 없음).

| 방법 (test 1,993문항) | R@1 | R@5 | R@10 | MRR@10 |
|---|---|---|---|---|
| BM25 Kiwi 내용어 | 0.658 | 0.913 | 0.965 | 0.769 |
| KURE-v1 공개 모델 (청크 MaxP) | 0.642 | 0.903 | 0.954 | 0.753 |
| **KURE-v1 미세조정 (청크 MaxP)** | **0.685** | **0.949** | **0.975** | **0.798** |
| KURE-v1 공개 모델 (512에서 자름) | 0.434 | 0.688 | 0.778 | 0.542 |
| KURE-v1 미세조정 (512에서 자름) | 0.493 | 0.747 | 0.839 | 0.606 |
| RRF (BM25 Kiwi 내용어 + 미세조정 KURE) | 0.699 | 0.956 | 0.983 | 0.811 |

dev(709문항): 공개 KURE R@1 0.690 / R@5 0.914 / MRR 0.788 → 미세조정 0.687 / 0.934 / 0.800 (R@1은 그대로, R@5·MRR 상승).

- **미세조정으로 공개 모델 대비 R@1 +4.3%p, R@5 +4.6%p, MRR +0.045. 형태소 BM25를 처음으로 넘었다.**
- McNemar (test, 같은 질문 쌍): R@1 미세조정만 맞힘 236 vs 공개 모델만 맞힘 149, p = 1.1e-5 / R@5 122 vs 31, p = 5.8e-14.
- 주의:
  - 질문 1,993개가 문단 71개를 공유해서 질문끼리 독립이 아니다 → p값은 낙관적으로 봐야 한다.
  - train과 test 회사가 같다 (10개사, 문단만 다름) → 회사별 문체에 적응한 효과가 섞였을 수 있다.
  - positive를 BM25로 골랐으므로 BM25와 비슷한 신호를 배웠을 가능성이 있다.
- 본 실험 계획: Dartdoc·원문 청크에서 LLM으로 질문을 만들어(생성 LLM ≠ 시스템 LLM, 검수 비율 기록) 수천 쌍을 만들고, **같은 회사 다른 사업연도 문단을 hard negative로**, 평가 회사·기업-연도와 겹치지 않게 다시 학습한다. 비교는 자체 평가셋으로.

## 8. 한계와 다음 단계
- Dartdoc은 대형사의 2022–2023 사업보고서가 거의 없고 표 숫자가 빠져 있다 → 평가 코퍼스는 OpenDART 원문 파싱(안 A)을 추천.
- FinDartBench는 근거 문단이 195개뿐이고 LLM이 만든 질문이며 라벨 노이즈가 있다 → 예비 결과로만 쓰고, 결론은 자체 평가셋(약 200문항, 30%는 사람 작성)으로.
- T6는 FinDartBench train 문단으로 만든 쌍이라 문단 수(99개)가 적고, train과 test의 회사가 같다. 본 실험은 Dartdoc·원문 청크에서 LLM으로 질문을 만들고(생성 LLM ≠ 시스템 LLM), 같은 회사 다른 사업연도 문단을 hard negative로 써서 다시 학습한다.
- 다음 할 일: 대상 기업 30개 보고서 원문 수집·청킹 → 학습 쌍 생성 → 평가셋 검수 기준 문서 → BM25 + LLM 기준선 end-to-end (9주차).
